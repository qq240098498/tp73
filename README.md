# tp73 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5073>

端口固定为 `5073`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存文案时会记下是谁改的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 文案区顶部可以按模块筛选、可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
5. 点新建文案，填上模块、文案键与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言与删除文案都会先确认
7. 用语清单区在文案区下面，可以维护两类用语规则并随时增删改；在检查条上选定模块与语言范围点“开始检查”，会逐条列出命中位置

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 用语规则与检查

用语清单里维护两类规则，每条规则都可以指定生效范围（**全部语言**或**其中几种语言**），随时可以新增、编辑、删除：

- **应当统一（unify）**：写清“现在常见的写法”与“应当改成的写法”。检查时只要译文里出现常见写法就报一处命中，并提示改成统一写法。
- **不能出现（banned）**：列出一律禁用的词语。检查时只要译文里出现这个词就报一处命中；“修改建议”可留可填，填了会在结果里一并给出。

规则保存时要当场成立，不成立会拒绝并指出是哪一条，常见情形包括：

- “应当统一”的两种写法填得一模一样，或应当改成的写法留空；
- 命中写法为空、超长；
- 生效范围选了指定语言却一种都没勾，或勾选的语言没有登记过；
- 同类型、同样的命中写法在重叠的语言范围上重复登记；
- 同一条译文会同时被“应当统一”和“不能出现”两类规则命中（两类规则命中写法相同且范围重叠）；
- 某条统一规则要求改成的写法，正好被重叠范围上的禁用词规则禁止（改过去仍然不通过）。

规则只在其生效语言范围内参与检查；范围不重叠的两条规则互不影响。删除一种语言时，会自动把它从指定了该语言的规则范围里摘掉，摘光后规则进入休眠（范围留空、不再命中任何语言），重新编辑设置范围即可恢复。

执行检查时在检查条上选定**模块**（全部模块或某一个）与**语言范围**（全部语言或勾选几种），结果逐条列出每一处命中，写清：文案键、语言、命中片段、它在整条译文中的位置（高亮显示）、命中的是哪一条规则（类型、写法与规则 id）以及处理建议。同一片段在一条译文里出现几次就列出几条；空着待翻译或未登记该语言的格子不参与检查。

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "entries": [...], "rules": [...] }`。用语规则形如：

```json
{
  "id": "rule-2002",
  "type": "unify",
  "phrase": "30 minutes",
  "replacement": "{minutes}",
  "scope": { "all": false, "languages": ["en-US"] },
  "note": "支付倒计时必须用 {minutes} 占位符，不能写死分钟数",
  "createdAt": "2026-09-12T08:05:00.000Z",
  "updatedAt": "2026-09-12T08:05:00.000Z"
}
```

`type` 为 `unify`（应当统一）或 `banned`（不能出现）；`scope.all` 为真时对全部语言生效，否则只对 `scope.languages` 里列出的语言生效。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据，旧数据文件缺少 `rules` 这一段时会补上内置的示例规则。

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/entries           | 文案列表，支持按模块与关键词筛选             |
| POST   | /api/entries           | 新增文案                                     |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案                                     |
| DELETE | /api/entries/:id       | 删除文案                                     |
| GET    | /api/rules             | 用语规则清单                                 |
| POST   | /api/rules             | 新增用语规则                                 |
| PATCH  | /api/rules/:id         | 修改用语规则                                 |
| DELETE | /api/rules/:id         | 删除用语规则                                 |
| POST   | /api/checks            | 按模块与语言范围执行一次用语检查，返回逐条命中 |

新增/修改规则的请求体形如 `{ "type": "unify", "phrase": "帐号", "replacement": "账号", "scope": { "all": true }, "note": "" }`；执行检查的请求体形如 `{ "module": "common", "scope": { "all": false, "languages": ["zh-CN"] } }`，`module` 与 `scope` 留空（或 `scope.all` 为真）时分别表示全部模块、全部语言。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
