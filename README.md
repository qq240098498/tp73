# tp73 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。文案区下面还有一块用语清单，可以维护“应当统一的写法”和“一律不能出现的词语”两类规则，选定模块与语言范围执行一次检查，命中的位置逐条列出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5073>

端口固定为 `5073`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存文案时会记下是谁改的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 文案区顶部可以按模块筛选、可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
5. 点新建文案，填上模块、文案键与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
6. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言与删除文案都会先确认
7. 文案区下面是用语清单。点新增规则可以维护两类规则：
   - **应当统一的写法**：写清“现在常见的写法”和“应当改成的写法”，检查时凡出现常见写法就命中，结果里给出目标写法
   - **一律不能出现的词语**：检查时凡出现这个词语就命中，需要删除或改写

   两类规则都要指定生效范围，可以选全部语言，也可以只勾选其中几种语言；规则随时可以编辑或删除
8. 在检查条上选定模块与语言范围，点执行检查，命中的每一处都会逐条列出：属于哪个模块、哪个文案键、哪种语言、命中的片段（连同前后文字高亮）、命中的是哪一条规则，以及在译文中的字符位置

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

保存规则时不成立会被当场拒绝，并指出是哪一条、哪个输入项的问题，例如：两种写法填得一模一样；生效范围留空或选了没有登记过的语言；同一生效范围内规则重复；一个常见写法被要求改成两种目标写法；目标写法又是另一条规则的常见写法（会反复命中）；同一条译文会同时被“应当统一”和“不能出现”两类规则命中。删除语言时，如果还有规则把生效范围指定到这种语言，也会先被拦下。

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "entries": [...], "termRules": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

用语规则按类型分两种结构：

- 统一写法：`{ id, type: "unify", from, to, scopeType, languages, note, createdAt, updatedAt }`
- 禁用词：`{ id, type: "banned", term, scopeType, languages, note, createdAt, updatedAt }`

其中 `scopeType` 为 `all` 时对全部语言生效，`languages` 为空数组；为 `languages` 时只对 `languages` 里列出的语言代码生效。

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/entries           | 文案列表，支持按模块与关键词筛选             |
| POST   | /api/entries           | 新增文案                                     |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案                                     |
| DELETE | /api/entries/:id       | 删除文案                                     |
| GET    | /api/term-rules        | 用语规则清单                                 |
| POST   | /api/term-rules        | 新增用语规则                                 |
| PATCH  | /api/term-rules/:id    | 修改用语规则                                 |
| DELETE | /api/term-rules/:id    | 删除用语规则                                 |
| POST   | /api/term-rules/check  | 按模块与语言范围执行一次检查，逐条返回命中   |

检查请求体形如 `{ "module": "home", "languages": ["zh-CN"] }`，两个字段都可省略或留空：模块留空表示全部模块，语言留空表示全部已登记语言。每条命中包含文案键 `key`、模块 `module`、语言 `language`、命中片段 `snippet`、片段在译文中的下标 `index` 与长度 `length`、命中的规则编号 `ruleId`、规则文字 `ruleLabel` 以及统一写法时的建议写法 `suggest`。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。用语规则相关的错误码主要有：`TERM_SAME_FORM`（两种写法一模一样）、`LANGUAGE_UNKNOWN`（范围里的语言没登记过）、`TERM_SCOPE_EMPTY`（生效范围留空）、`TERM_DUPLICATED`（规则重复）、`TERM_TARGET_CONFLICT`（同一写法被要求改成两种目标）、`TERM_CHAIN_CONFLICT`（目标写法又是另一条规则的常见写法）、`TERM_CROSS_CONFLICT`（同一条译文同时被统一与禁用两类规则命中）、`TERM_RULE_SCOPE_IN_USE`（删除语言前还有规则引用它）。
